2.13.6 # October 30, 2026 Latest
macOSWindowsLinux

A calmer, smoother workspace

Edit a sent message and continue from there, stop any running command, copy whole answers, and a long list of scrolling, sidebar and animation fixes.

New

  • Edit a sent message right in the chat, like Claude Desktop: Enter sends, Esc cancels, and the conversation continues from that point. The original stays in your session history.
  • Stop a running command or background task from the chat or the Tasks panel.
  • Select and copy across headings, paragraphs and lists of an answer in one go.

Improved

  • Long commands and their output open instantly in a scrollable box, and scrolling hands back to the chat at the edges.
  • Reopened chats show background task results as a short note instead of raw tags, and pasted text no longer shows its markup.
  • Commands in the chat and the Tasks panel are easier to read, with the command shown next to its description.
  • The hidden sidebar and changes panel open from the window edge without flickering, no longer open when you reach for the chat scrollbar, and stay open while a menu is shown.
  • The chat keeps your reading position when the window or a panel changes width, and no longer pulls you back down right after you open a session.
  • Diffs keep their place while comment threads load, the file list follows as you scroll, and the conversation refreshes without jumping to the top.
  • Transitions are a touch slower and no longer blur text.
  • Scrolling inside a code block or output no longer stops the chat from following new messages.

Fixed

  • The changes panel no longer runs past the window edge in narrow windows.
  • Text in long answers no longer overlaps the next message.
  • The hidden Files tab no longer reacts to review keys.

No changes for this platform in this release.

2.13.5 # October 27, 2026
macOSWindowsLinux

Reviews that read like code

Diffs wrap at word boundaries with syntax colours, a split view and review keys, a command palette opens with ⌘K / Ctrl+K, and PullYard now tells you when a review, a failed check or an agent needs you.

New

  • Command palette on ⌘K (Ctrl+K on Windows and Linux): jump to any section, pull request, issue or repository, paste a PR link, or run an action. Go to Session moves to ⇧⌘K / Ctrl+Shift+K.
  • Diffs have syntax highlighting and a Unified / Split switch for wide windows.
  • Review from the keyboard in Files changed: N/P next and previous file, ]/[ next and previous change, V viewed, W wrap, S split.
  • Notifications for a new review request, failed checks on your pull request, and approvals or requested changes, each with its own switch in Settings. Clicking one opens the pull request.
  • The Dock icon shows how many reviews are waiting, and optionally agents that need you.
  • The taskbar badge counts reviews waiting, and optionally agents that need you.
  • A Keyboard Shortcuts window (Ctrl+?) lists every shortcut.
  • Select diff lines with the mouse and copy them with Ctrl+C, or right-click to copy a line or a whole change.
  • Customize the pull request toolbar from View → Customize Toolbar…; navigation now lives in a new Go menu.

Improved

  • Long code lines wrap at word boundaries with a hanging indent instead of breaking mid-word, or turn wrapping off and scroll sideways.
  • The changes panel next to an agent chat can be resized by dragging its edge, and Expand shows the diff over the chat (Esc to go back).
  • Pull request lists are easier to scan: full titles on hover, bigger avatars, and checks, reviews and comments grouped on the right. Drafts get their own icon.
  • Empty lists explain what shows up there, a filter with no results offers Clear filter, and errors come with Retry.
  • A new welcome screen where the logo draws itself, and loading spinners are replaced by the animated logo.
  • Review, Fix with agent and Merge are labelled in the pull request toolbar.
  • The Comment button stays neutral until you type and shows Sending… while it posts.
  • Screen readers can now name icon-only buttons, status icons and list rows across the app.
  • Sidebar icons use one colour, and only counts that need your attention are highlighted.
  • Colours follow Windows High Contrast.
  • Colours build on the GNOME palette and follow high contrast.
  • When an agent asks for permission, the bottom banner only appears once the request scrolls out of view.

No changes for this platform in this release.

Agents, signed updates and Jira

The Claude Code workspace becomes Agents: grouped tool runs, rewind from any message, pull requests opened from a session, a session switcher with full-text search, and notifications. Updates are now signed, and pull requests can show their Jira ticket.

New

  • Agent chats group consecutive tool calls into one line such as Ran 3 commands, read 2 files, with the running step shown while it works. Thinking appears as its own step.
  • Copy any message, or edit one of yours to continue from that point in a new branch of the session. The original session stays as it was.
  • A jump-to-latest button with a count of new messages when you scroll up, and a pinned plan above the composer.
  • Open a pull request with the agent: it commits, pushes and writes the description, and a card opens the new pull request right in PullYard. Commit and push with agent when the branch already has one.
  • A session sidebar with sub-sessions, pin, rename and archive, and status dots for working, finished and waiting sessions.
  • Notifications when a session finishes or needs you, with a badge on the Dock, taskbar or launcher.
  • A session switcher (⌘K / Ctrl+K) that also searches inside conversations, plus shortcuts for a new session and the next or previous one.
  • A start screen with the project's branch and changes, suggestions for what to do next and recent sessions; open the project in your editor, terminal or file manager.
  • When the agent's sign-in expires, Sign in again opens the login in a terminal and resumes the session afterwards. Messages sent before a session starts are kept, images included.
  • A Jira tab on pull requests: connect in Settings, and the ticket from the title, branch or description shows with its status, which you can change from PullYard.
  • Agents can leave notes, questions and decisions on pull requests in your stack. They stay on your computer, like your own notes.
  • A self-drawing logo replaces the spinners, and lists and pull requests have a Refresh button.

Improved

  • Updates are signed. PullYard checks the signature before installing and refuses an update that doesn't match.
  • While a GitHub rate limit is in effect, PullYard stops sending reads until it resets.
  • macOSMuch lighter: a smaller download, less memory in the Agents section, smoother scrolling in long chats and no background animations while idle.

No changes for this platform in this release.

Stacked pull requests on Windows and Linux

  • The stack strip on a pull request follows stacks that branch, and a stack loads with one request per repository and is cached on disk, so it shows up instantly.

2.10.0 # October 17, 2026
macOSWindowsLinux

GitLab, Bitbucket and more accounts

PullYard now signs in to GitLab, Bitbucket, Gitea and GitHub Enterprise next to GitHub. Keep several accounts, give each one its own Claude Code sign-in, and lock an account with a PIN if you share your computer.

New

  • Sign in to GitHub Enterprise Server, GitLab (gitlab.com or self-managed), Bitbucket Cloud and Gitea / Forgejo, including Codeberg. Use gh or glab, a personal access token, OAuth Device Flow (GitHub, GitHub Enterprise and GitLab), or your Atlassian email and an API token for Bitbucket.
  • GitHub Enterprise works like github.com: every list, the diff viewer, reviews, checks and Projects.
  • For GitLab, Bitbucket and Gitea: review requests, your merge or pull requests (also grouped by project), mentions, issues, repositories and the service's inbox (the GitLab To-Do List, Gitea notifications), wherever the service offers them. GitLab uses its own words: merge requests and !12. Reviews for these services still open in the browser.
  • Keep several accounts and switch between them from the sidebar or Settings. Your GitHub account carries over without signing in again.
  • Each account has its own Claude Code sign-in. The first account keeps the Claude Code you already use; an account you add starts with a separate profile you sign in to once. Switching keeps every sign-in, and PullYard only shows the active account's Claude Code profiles.

Safety

  • An optional PIN (4 to 6 digits) per account, asked when PullYard starts with that account and when someone switches to it. Only a salted hash is stored, in the system keychain. After 5 wrong PINs PullYard pauses, and after 10 it blocks unlocking until the PIN is reset.
  • macOSUnlock with Touch ID. It turns off for the account when the fingerprints on the Mac change, so a newly added finger can't open it. A forgotten PIN is reset with your Mac password.
  • WindowsUnlock with Windows Hello.
  • Resetting a PIN, or signing out of an account, signs out only that account's Claude Code profiles.

Improved

  • PullYard checks for updates every time it starts, so Update to … no longer disappears after a restart. The update window still appears only once per version.

No changes for this platform in this release.

Fix failing CI with Claude Code

When checks fail on a pull request, PullYard gathers the part of the log that matters and hands it to Claude Code, ready for you to review and launch. Windows also gets a brand theme that finally matches the rest of PullYard.

New

  • A N checks failing · Fix with Claude Code banner on pull requests with failing checks, plus Fix with Claude Code on every failing check and in the CI log view.
  • PullYard finds the failing step in each GitHub Actions log, keeps the error and the lines leading up to it, adds the check's annotations, and opens the Fix sheet with a ready prompt. Nothing runs until you click Launch.
  • Checks from other CI services contribute their title, summary and details link.
  • Re-run failed jobs for GitHub Actions, after a confirmation.
  • macOSInstall with Homebrew: brew install --cask pullyard/tap/pullyard.

Safety

  • Logs, check names and pull request titles go to the agent inside clearly marked blocks with a random marker, labelled as data rather than instructions, so a pull request can't smuggle commands into the prompt.
  • Logs are streamed and trimmed to the failure, so a huge log doesn't fill memory, and your GitHub token is never sent to the log storage host.

Improved

  • WindowsThe PullYard theme no longer shows Windows' default gray: the list, filter box, comment box, buttons, menus and dialogs use PullYard's colors in dark and light.
  • WindowsWindows contrast themes keep their system colors, and badges and buttons stay readable in them.
  • WindowsThe selected sidebar item is easier to tell apart from the one under the pointer, and Settings and Diagnostics update right away when you switch themes, keeping keyboard focus.

No changes for this platform in this release.

Lighter sync, instant lists and git blame

PullYard now talks to GitHub far less: in a 20-minute session on macOS traffic dropped from 7.9 MB to 1.1 MB. Lists open instantly from a local cache, and you can see who wrote every line.

New

  • Git blame in the repository code browser: author, date and commit for every block of lines, with a heat stripe for recent changes. Click a block to open its commit. Turn it on with the Blame button, or Blame on a file in a pull request.
  • macOSToggle blame with ⌥⌘B.
  • Toggle blame with Ctrl+Alt+B.
  • Copy short link copies owner/repo#123 from the pull request or issue header and from the right-click menu on list rows and notifications.
  • macOSCopy the short link of the open pull request or issue with ⇧⌘C, or right-click a row in the menu bar inbox.
  • Copy the short link of the open pull request or issue with Ctrl+Shift+C.
  • Diagnostics in Settings: an optional panel with every request to GitHub, its time, size and rate limit, plus background refresh timings. Off by default; export to share with a bug report. Tokens and request bodies are never recorded.
  • The website shows screenshots and the product tour of the platform you're on.

Faster

  • Background refresh updates only the screen you're looking at. Other sections catch up when you open them.
  • Notifications are fetched only when they change, and the menu bar badges use a much smaller request.
  • An open pull request is refreshed with a small check and fully reloaded only when something changed, or every five minutes.
  • Files of a pull request load when you open the Files tab, not before.
  • Lists open instantly from a cache on disk, kept per account and removed when you sign out, and they still show when you start offline.
  • Stacked pull request lookups are cached instead of repeated on every refresh.
  • LinuxQuick open and @ file completion search as you type without stalling, CI logs switch between all lines and errors instantly, and Claude replies stream without redrawing the whole chat.
  • LinuxLarge diffs update in about 17 ms instead of up to 230 ms, the projects board no longer redraws while you drag, and label colors load in one pass.
  • LinuxThe repository README loads only when you scroll to it, and the app is about 20% smaller.

Reliability

  • Reads that fail on a dropped connection or a 502–504 from GitHub are retried once. Changes such as merges and comments are never sent twice.
  • When GitHub's rate limit is reached, background refresh pauses until it resets and tells you so.
  • The Claude chat no longer jumps to the bottom while you're reading earlier messages.

Fixed

  • WindowsA crash in the code viewer.
  • LinuxThe Claude workspace no longer shows "No Claude Code sessions yet" under an existing session, and the account avatar is round again.

No changes for this platform in this release.

2.7.0 # October 15, 2026
macOSWindowsLinux

Security and reliability hardening

PullYard holds your GitHub sign-in and drives Claude Code in your repositories, so we audited every platform and closed the gaps we found.

Security

  • Links in pull requests, comments and Claude replies open only when they are http, https or mailto. Local files and custom app schemes are ignored.
  • Git commands ignore repository settings that could run code, such as core.fsmonitor and external diff drivers, so opening an untrusted clone is safe.
  • macOSpullyard://claude/new links now ask before starting a Claude session and show the folder and prompt. A link can no longer pick the permission mode.
  • WindowsFix with Claude Code in a terminal passes the prompt through a temporary file instead of the command line, so PR titles and review comments can't inject shell commands.
  • WindowsOpen on a file Claude edited works only inside the session folder. Scripts and programs are shown in Explorer instead of being run.
  • WindowsThe chat view no longer loads remote images, and your GitHub token is sent only to api.github.com.
  • LinuxThe WebKit sandbox stays on. If your system can't run it, PullYard explains how to opt out with PULLYARD_DISABLE_WEBKIT_SANDBOX=1.
  • LinuxPull request pages run under a strict Content Security Policy.

Reliability

  • If your token can't be saved to the system keychain, you see the error at sign-in instead of being signed out after a restart.
  • A damaged settings file is kept as settings.json.corrupt instead of being silently overwritten, and settings are flushed to disk before they replace the old file.
  • macOSGit and GitHub CLI calls time out instead of hanging, and PullYard no longer quits if Claude exits while it is sending a message.
  • WindowsAn unexpected message from Claude no longer leaves a chat stuck in the busy state. Background errors are written to errors.log.
  • LinuxStopping a chat stops Claude and every tool it started. Sign-in keeps going through short network drops.

New

  • A changelog and a public roadmap on the website.
  • The update window links to What's new in all versions.

Heads-up

  • WindowsIf Claude Code is installed only as the npm claude.cmd shim and neither claude.exe nor Node.js can be found, launching a terminal session with a prompt now asks you to install one of them or use Copy.

No changes for this platform in this release.
